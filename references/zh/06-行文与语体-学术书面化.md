# 06 · 行文与语体：学术书面化（顶刊标准）

本文档管"用什么词句写"，是 `references/zh/01-文体规范-成稿零元信息.md` 的下游。分工必须分清：

| 文档 | 管什么 | 典型症状 |
|---|---|---|
| `01-文体规范` | 写成什么样（元信息、段落闭环、指标论证、诊断清单） | 正文残留【待核实】、段落没有收束、数字没有基线 |
| **本文档** | 用什么词句写（语体、词法、句式、语序） | 读起来像技术博客、口语残留、论断不前置、摘要不像摘要 |

两者不重叠：一段话可以"零元信息且逻辑闭环"，但读起来仍然像草稿——那属于本文档的管辖范围。

---

## 1. 顶刊语体的三条判据

判定语体是否合格，只看三条，每条都可以被机械检验。

**判据一：信息密度。** 删掉任何一个分句，信息量是否下降？若某个分句删掉后读者不损失任何事实或逻辑，它就该删。口语化行文最常见的形态就是"用两个分句说一件可以一个分句说清的事"。

**判据二：主语与动作明确。** 每个句子能回答"谁对什么做了什么"。被字句、把字句、无主句连续出现时，读者需要自行补主语，这就是翻译腔与口语感的来源。

**判据三：无口语残留。** 句子可以在正式会议报告中被朗读而不显得突兀。反过来说，任何会在组会口头讨论中出现、但不会出现在期刊正文里的表述，都属口语残留。

## 2. 禁用词与句式（机械扫描清单）

以下词表可直接用 `grep` 扫描 `.tex`／`.md` 正文（不含核实清单与内部文件）。**命中即需人工判定，绝大多数应改写。**

### 2.1 口语与网感词

| 禁用 | 问题 | 改为 |
|---|---|---|
| 拍小、拍大、拍得清 | 相机口语 | 成像尺度、目标像素跨度 |
| 对不上账、算不过来 | 财务比喻 | 无法逐项核对、与预期不符 |
| 重灾区、踩坑、坑、翻车 | 网络语 | 高发环节、常见错误、失效情形 |
| 搞、弄、折腾 | 泛动词 | 实现、构造、处理、求解 |
| 说白了、简单说、一句话 | 讲解口吻 | 直接给出结论句 |
| 挺、蛮、特别、超级 | 程度副词口语 | 删除，或换成具体数值 |
| 一眼看出、肉眼可见 | 非正式 | 可直接观察、表观上显著 |
| 不是……而是…… | 口语对比，且常掩盖因果 | 该现象反映的是……而非…… |
| 这把……、这样搞 | 指示代词+口语动词 | 指代明确的名词短语+正式动词 |
| 其实、说白了、事实上（滥用） | 填充词 | 删除 |

### 2.2 AI 套话与空洞连接词

| 禁用 | 问题 | 改为 |
|---|---|---|
| 综上所述、总而言之、总的来说 | 无信息收尾 | 给出该节的判断句（带结论或数字） |
| 值得注意的是、需要指出的是 | 滥用后成为噪音 | 全篇最多用一次；其余直接陈述 |
| 不仅……而且……、一方面……另一方面 | 堆叠后稀释论点 | 拆成两个独立句，各自带证据 |
| 具有重要意义、起到了重要作用 | 无论断 | 具体说明改变了什么、改变了多少 |
| 随着……的不断发展 | 万金油开头 | 直接给出现状的数字或事实 |
| 为……提供了新的思路 | 空泛 | 说明该思路解决的具体问题 |

### 2.3 论断强度类（与 `references/craft/claim-evidence.md` 联动）

| 禁用 | 改为 |
|---|---|
| 显著提升、大幅提高、明显改善（无数字） | 给出具体数值与比较对象 |
| 效果很好、性能优异 | 给出指标与基线 |
| 完全解决、彻底消除 | 说明覆盖范围与前提条件 |
| 首次提出（无检索证据） | 删除，或限定为"在本文检索范围内" |

## 3. 句式改写规则

**规则一：论断前置。** 段落首句必须是该段的论断，不能是背景铺垫或过渡句。读者读完首句就应知道这段要证明什么。

- 不合格：`近年来，多模态数据受到广泛关注。为了获取这类数据，研究者尝试了多种仿真途径。`
- 合格：`现有仿真途径无法同时满足几何一致与批量产出两项要求，这是本文要解决的问题。`

**规则二：一句话承载一个判断。** 用句号切分并列的判断，不要用逗号串接三四个分句。中文长句的典型病灶是"逗号句"——一个句号内套四层因果，读者读到末尾已忘记主语。

**规则三：避免"把"字句与"被"字句连用。** 连续两句出现"把……"或"被……"，改为主动语态并明确主语。

**规则四：动词优先于名词化。** "进行了分析"→"分析"；"实现了对……的优化"→"优化了……"。名词化堆叠是翻译腔的主要来源。

**规则五：术语一次定义、全文稳定。** 首次出现写"全称（缩写）"，此后只用缩写，不得混用两个名字指同一事物。改缩写必须全文替换，包括图题、表头与公式下标。

## 4. 摘要的五段结构（中文顶刊）

摘要不是引言的压缩，而是全文的最小可独立阅读单元，须严格按五段写，顺序不可调换：

1. **现状与重要性**（1 句）：该问题为什么值得做。不带文献、不带背景铺陈。
2. **缺口**（1–2 句）：现有做法的具体不足，须指出类别而非罗列人名。
3. **方法**（2–3 句）：本文提出什么，核心机制是什么（不是"提出了一个框架"这种空壳，要说清关键设计）。
4. **定量结果**（2–3 句）：在什么规模的数据／配置上，得到哪些可核对的数字。至少包含一个绝对量、一个相对偏差或对比量。
5. **判断**（1 句）：这些结果支持什么结论，或指出适用边界。不许写"具有重要价值"。

**长度**：中文摘要 250–350 字。**禁忌**：出现"本文首先……然后……最后……"的流水账句式；出现未在正文验证的数字；出现引用标记。

---

## 5. 数字与量词的硬约束

1. 每个定性形容词都应能替换为数字。写不出来，说明该判断缺乏依据，应删除而非保留。
2. 百分比与百分点严格区分：写"提升 3 个百分点"，不写"提升 3%"；相对提升须显式标注"相对"。
3. 区间写"39.02--51.81 分贝"，不写"约 40--50 分贝"；有效数字位数与测量精度匹配，不随意补零。
4. 同一指标在摘要、正文、表格、结论中的数值必须逐字一致（含位数与单位）。
5. 单位与量符号按 `references/zh/02-IEEE中文会议论文骨架.md` 的写法，列头标方向（`参数量/M$\downarrow$`）。

## 6. 真实改写案例（来自实际交付稿）

以下五组均取自真实交付经历的"初稿 → 修订稿"，可作为改写标尺。

**案例一：口语对比句**

- 初稿：`这一比例不是把目标"拍小"，而是机载相机在真实斜距上的成像结果。`
- 修订：`该比例反映的是机载相机在真实斜距上的成像结果，而非人为缩放；其数值逐帧记录于数据元信息。`
- 要点：去掉"拍小"这类相机口语；把隐含的两个判断拆成一个陈述加一个否定限定。

**案例二：比喻式诊断**

- 初稿：`仿真数据的风险不是"看起来像"，而是"看起来像但对不上账"。`
- 修订：`仿真数据的主要风险并非"成像不像"，而是"成像合理却无法逐项核对"。`
- 要点：保留对比结构但换成可操作的表述；"对不上账"属财务比喻，必须替换。

**案例三：代价表述**

- 初稿：`这一取舍使框架能批量出数，代价是绝对辐射量不可直接用作测量值。`
- 修订：`该取舍使框架可在纯 CPU 上以秒级至十几秒级的单帧耗时批量出数，代价是绝对辐射量与雷达截面积不可直接用作测量值。`
- 要点：把"能批量"补成可核对的时间量级；"取舍—代价"是合法结构，保留。

**案例四：贡献条不落实**

- 初稿：`提出了一种高效的仿真框架，显著提升了数据生成效率。`
- 修订：`提出统一三维世界驱动的多模态仿真框架，在同一帧内生成六路输出，全流程运行于纯 CPU 离线环境，单帧耗时 2--19 秒。`
- 要点：删掉"高效""显著提升"这类无法核对的判断，换成机制加数字。

**案例五：摘要流水账**

- 初稿：`本文首先介绍了研究背景，然后分析了现有问题，最后提出了解决方法，并通过实验验证了有效性。`
- 修订：（按第 4 节五段式重写，每段只保留事实与数字）
- 要点："首先……然后……最后"是过程叙述，不是摘要；摘要只陈述结论与依据。

## 7. 交付前的语体自查（五步，逐条打勾）

1. **词表扫描**：把第 2 节的词表在本稿中逐词检索，命中项逐条判定并改写。
2. **首句检验**：抽读每一段的第一句，是否能独立成句并表达该段论断。不能则重写首句。
3. **删句检验**：随机抽三段，逐句尝试删除，凡删后不损失信息者一律删除。
4. **朗读检验**：朗读摘要与引言，凡读起来像口头讲解的句子标记并改写。
5. **一致性检验**：术语、缩写、指标名在摘要、正文、图表、结论中是否完全一致。

五步全部通过，方可进入编译验收。
