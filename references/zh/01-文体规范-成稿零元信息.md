# 01 · 文体规范与成稿零元信息

本文档是 `paper-writing` 技能中文轨道的文体依据，管的是“写成什么样”：交付的正文必须读起来像一份已经想清楚的成稿，而不是一份还在施工的草稿。分工如下——章节骨架与版式见 `references/zh/02-IEEE中文会议论文骨架.md`，实验数值的取法与占位登记见 `references/zh/03-实验数值与基准对齐.md`，本机工具链事实见 `references/zh/04-本地LaTeX工具链.md`，报错对照见 `references/zh/05-编译排错手册.md`。工具链路径与报错以 04、05 为准；文体的重写判据以本文档为准。

## 1. 三条铁律

铁律是判定式规则而非倡议：交付前逐条比对，任一条不满足即视为未完成，没有“基本符合”这一档。

### 1.1 铁律一：成稿零元信息

**规则**：交付正文（`main.tex` 的正文部分，以及由它编译出的 `main.pdf`）只允许出现“已经想清楚的成稿”内容；作者、审稿人、编辑在任何一页都读不到“这份稿子还在制作中”的痕迹。全部不确定性、待核实项、占位数值、写作指令，一律剥离到与论文同目录的 `核实清单.md`。

**判定**：把 `main.pdf` 当成陌生读者的第一次阅读——任何一句需要读者“知道内情才能读懂”，或“等作者补完才成立”，即判违反。

**违反的典型表现**：

- 正文残留【待核实】【TBD】【待填】一类标记；
- 图注、表注里写“数据待补”“出处见某某链接”；
- 段落里出现“建议采用”“可以考虑”“本文当前版本”；
- 写作指令残留：“此处插入架构图”“这里补一段消融分析”；
- 表格下方挂“形式审查自查表”“文件属性说明”等与论文内容无关的行政信息。

### 1.2 铁律二：数据诚信

> 本条是 `SKILL.md` §0 铁律二「数据与证据诚信」在数字侧的具体化。同一铁律的证据侧（论断强度不得超过证据强度、如何降级措辞）见 `references/craft/claim-evidence.md`，本条不重复。

**规则**：论文里的实验数值只有两种合法来源——用户实测结果，或公开基准论文的官方报告值（仅用于基线对比，且必须给出处：论文名、版本、表号）。若用户明确授权“按公开基准的量级填写”，填进去的只能是占位值，不是实验结果；占位值必须逐表逐行登记在核实清单中，并在交付时口头说明。带占位数值投稿属学术不端，这句提醒不可省略。

**判定**：对每一个出现在摘要、表格、结论里的数字，都能当场回答“它从哪来”与“它是否已被实测替换”。

**违反的典型表现**：

- 把官方基线值抄进“本方法”一列；
- 为凑故事凭空放大提升幅度（如无依据地写成 +5 个百分点）；
- 摘要、正文、表格、结论中的同一指标不相等；
- 提升量算错，或把相对提升与百分点混用；
- 占位值未登记，或登记了却口头不提。

### 1.3 铁律三：可编译是底线

**规则**：交付的每一版 `.tex` 必须当场编译验证。验收口径：退出码为 0、Missing character 为 0、LaTeX Error 为 0、multiply-defined label 为 0、PDF 抽取文本无乱码方块。只写不验的稿子不算交付。

**判定**：不看“我改得对不对”，只看编译日志与 PDF 抽出的文本。

**违反的典型表现**：

- 交付前根本没跑编译，把上一轮的 `main.pdf` 当成果；
- 编译存在中文缺字仍照交，正文出现成片方块；
- 复制图表代码块后 `\label` 重复，日志报 multiply defined 也不处理；
- 用 biblatex/biber 写参考文献，Tectonic 下引用全成 `[?]` 也不换写法。

## 2. 零元信息清单

### 2.1 正文禁止出现的内容

| 类别 | 禁止出现的形态 | 为什么不行 |
|---|---|---|
| 占位与待办标记 | 【待核实】【TBD】【待填】、`??`、`XX` | 读者读到的是一份未完成的稿子 |
| 来源标注与链接 | 正文或表注中的 arXiv 链接、DOI、“据某某论文表 3” | 出处应进参考文献，正文只留论证 |
| 合规与审查声明 | “本稿已通过形式审查”“查重率 xx%” | 与学术内容无关的行政信息 |
| 版本与流程口吻 | “本文当前版本”“初稿”“后续将补充” | 暴露写作过程，破坏成稿感 |
| 建议式措辞 | “建议采用”“可考虑”“不妨” | 论文陈述事实与判断，不做建议 |
| 写作指令残留 | “此处插入图”“下面补实验” | 是写给作者自己的便条，不是正文 |
| 文件属性声明 | “本文件由某工具生成”“模板版本 x”“字数统计” | 元信息，投稿系统与读者都不需要 |

同等适用于摘要、图注、表注、脚注与致谢；PDF 元数据里的标题、作者字段也要求干净。

### 2.2 唯一合法去处：`核实清单.md`

位置：与 `main.tex` 同目录，随论文一起交付。它不进入论文，不被 `\input`，不与正文混排。

必含的 5 个条目：

1. **占位数值逐表逐行**——表号、行名、列名、当前值，外加“必须替换为真实实验结果”的醒目说明与替换责任人（可留空待用户填）；
2. **基线数字出处**——每条基线给出论文名、版本（arXiv 号或期刊卷期）、表号，以及是否需要用户自行复现的提示；
3. **作者、单位、邮箱等待用户填项**——置顶，逐项列出当前占位内容与目标格式要求；
4. **图题与图内容核对项**——图文件名、当前题注、图实际内容、是否一致、需要改名还是换图；
5. **参考文献状态**——逐条标注：已正式发表 / arXiv 预印本（正式发表后更新出处）/ 未发表手稿（需作者确认可引）。

**处置原则**：清单里每一条都要能被勾选“已处理／未处理”；正文与清单同时交付，口头逐类说明哪些数字是占位值。

## 3. 段落闭环与指标论证

### 3.1 四拍闭环

每个自然段按“问题 → 机理 → 证据 → 收束”四拍推进，缺一拍即视为未闭环。

- **问题**：本段要解决的具体困难，一句话，落在可观测的现象上；
- **机理**：为什么这样设计能解决，写成因果链，不用形容词代替因果；
- **证据**：来自公式推导、消融、对比表或可视化的支撑，明确指到具体表、图、式；
- **收束**：一句把本段结论钉死；实验段的收束必须落到数字，不许用“显著提升”四个字了事。

### 3.2 指标写法：一句指标＋一段论证

任何进入正文的关键指标，都写成“一句指标＋一段论证”的结构：

1. **一句指标**：一句话给出指标名、单位与优劣方向，例如“以单帧推理时延（毫秒，↓）作为实时性指标”；此句只陈述指标本身，不夹带比较与解释。
2. **一段论证**：按“现有水平基线 → 本项目方法 → 因此定为该值”三步展开。基线一步要说清谁、在什么条件下、达到什么水平；方法一步说清结构上做了什么、为什么这个量级合理；最后一步把前两步接起来，让读者知道这个数是结论而不是愿望。

三步缺一不可：缺基线，数字没有参照系；缺方法，读者不知道差距从哪来；缺“因此”，指标就只是被宣告，没有被论证。

### 3.3 对照：不合格写法与合格写法

**第一组（方法段，缺机理与证据）**

- 不合格：“本模块采用注意力机制，有效提升了跨模态特征的融合能力，显著增强了模型的表达能力。”——三句全是形容词，没有回答“为什么需要”“怎么融合”“凭什么说有效”。
- 合格：“两路特征的空间分辨率不一致，直接相加会把细粒度一路抹平；本模块先在粗粒度上做通道注意力，再把权重上采样回细粒度，从而在不加深主干的前提下对齐两路感受野；消融表显示，只保留通道注意力时增益已接近完整模块，说明增益主要来自权重对齐，而非额外参数。”——问题、机理、证据、收束四拍齐全。

**第二组（实验段，收束不落数字）**

- 不合格：“从表 4 可以看出，本文方法在复杂环境下表现更好，说明所提方法具有较好的鲁棒性。”——结论无量化、无对照、无机理。
- 合格：“表 5 的雾天与低照度两个子集上，本方法对最强基线的领先幅度均大于表 4 的总体领先幅度，并随退化程度加深而单调增大；这与双分支互补的机理一致——光学支路失效时，合成孔径雷达（Synthetic Aperture Radar，SAR）支路仍能提供结构信息。”——收束落在可核对的表值与单调趋势上，并回到机理。

### 3.4 收束的三条硬判据

- 段内出现的数字必须与表格同源，不许在正文另生一套；
- 不许用“显著、大幅、明显”代替量，“提升多少”要可心算复核；
- 一段只允许一个结论；出现两个结论就拆段。

## 4. 读稿诊断清单（机械执行）

诊断顺序固定为：静态扫描（第 1—3、6 项）→ 逻辑扫描（第 4、5 项）→ 编译一次（第 7 项与编译期问题）。结论写成“问题列表”，每条含位置（文件＋行号／图表号）、问题描述、处理动作。

| 序号 | 扫描项 | 怎么扫 | 命中怎么处理 |
|---|---|---|---|
| 1 | 占位符 | 全文搜 `待填|待补|待核实|TBD|建议|模板|blankfigure|??`，并检查空表、空图位 | 从正文剥除，逐条搬进核实清单；数值类同步登记到对应表行 |
| 2 | label 冲突 | 提取全部 `\label{...}` 做重复计数，再检查 `\ref`／`\eqref` 有无悬空 | 重复的按图／表／式重命名（`fig:`／`tab:`／`eq:` 加语义名），全文替换引用；悬空引用补 label 或删掉该句 |
| 3 | 图题与文件名一致 | 逐图比对 `\includegraphics` 路径、图内文字、题注三者 | 图改用途时同步改名与题注，并在核实清单登记核对项；不得保留旧名 |
| 4 | 引用完整性 | `\bibitem` 与 `\cite` 双向比对 | 有 cite 无条目：补条目或删 cite；有条目无 cite：补引用或移出；未发表条目在清单标状态 |
| 5 | 数字一致性 | 摘要、正文、表格、结论四方对照同一指标，提升量当场心算 | 以表格为唯一真值源，其余各处改到与表相等；算错的提升量重算后回填 |
| 6 | 命名一致性 | 全文搜方法名、模块名、缩写，统计变体 | 术语首次出现给全称＋缩写，之后统一用缩写；改缩写要全文替换，含图表题注 |
| 7 | 作者／单位／邮箱 | 检查 `\author` 块与首页脚注 | 无法代填，正文保留占位并置顶核实清单，交付时口头提醒 |

**图表纪律（同属诊断范围）**：每图每表都必须在正文被引用（“如表 5 所示”）并紧跟一段解读；表注写清指标方向（↑／↓）与加粗、下划线约定。诊断时把“图在正文中从未被提及”单列一条问题。

## 5. 局限与比较的写法

### 5.1 诚实但有立场

- 局限的句式：在什么条件下、哪一类指标、相对哪条基线，出现了多大差距；差距的来源是设计取舍，还是数据与硬件限制。
- 立场：指出取舍是为了换取什么，而不是“我们做得还不够好”；代价与收益要同时出现。
- 禁止贬低式表述：不写“某方法显然粗糙／过时／不可用”，改写为“某方法在某条件下依赖强假设，本文在另一条件下放松了该假设”。

### 5.2 假局限的反例（评审最反感）

- **客套式**：“由于时间和实验条件限制，本文工作仍有不足，未来将进一步改进。”——没有信息量，等于承认没想清楚。
- **自我贬低式**：“本文方法在效率上不如现有方法，这是明显缺陷。”——若效率并非本文主张，应改写为取舍陈述；若确是短板，给出量与适用边界。
- **伪局限**：“本方法仅在某数据集上验证，泛化性有待验证。”——单数据集验证是事实陈述，不是局限；要么补数据集，要么写清该数据集的代表性边界。
- **把范围写成局限**：“本文只考虑双模态融合，未考虑三模态。”——除非三模态是本文主张的必要条件，否则这是范围声明。

### 5.3 三条判据

1. 每条局限都能对应到正文某处的设计选择；
2. 每条局限都给出可检验的边界（条件、指标、差距方向）；
3. 局限段不引入新概念、新符号，避免评审追问未定义内容。

## 6. 交付格式

- 交付物两个：`main.pdf`（已按第 1.3 条验收）与 `核实清单.md`（已按第 2.2 条五项齐全）。
- 用 present 工具把两个文件一并交付；清单内容不得混进正文，清单本身也不改造成论文的组成部分。
- 口头汇报四件事：做了哪些章节级改动、哪些数字是官方基线值、哪些是本方法占位值、用户必须亲自处理什么（作者信息、占位数值替换、参考文献状态）。
- 汇报话术固定包含风险提示：“带占位数值投稿属学术不端，投稿前必须替换为真实实验结果。”
- 新建论文项目以 `assets/ieee-cn-template.tex` 为骨架起点，骨架与版式细则见 `references/zh/02-IEEE中文会议论文骨架.md`。
